## 本輪最貴的三個教訓

1. **開錯 App 版本，症狀完全像功能故障。** 清空資料庫後重開，實際開到的是
   `/Applications/MyHealthBank.app`（v0.5.0：schema v3、12 張表、沒有 CPAP
   adapter、沒有錯誤卡）。而它與 dev 版**共用同一個資料目錄**。當時的症狀是
   「CPAP 資料夾拖進去毫無反應、Apple 正常、新庫是 12 表 v3」，我一度誤判為
   `DDL` 沒有 CPAP 表（那是我的 regex 只匹配到片段，`DDL` 其實有 15 張表）。
   **規則：症狀不合預期時，先確認執行的是哪個 binary**（`ps aux`）。已在
   匯入頁標出版號與執行來源。
2. **新增資料表要接上七處清單，漏任一處都不會有錯誤訊息。** CPAP 三表當初
   漏接了六處，本輪逐一實測才發現：來源檔刪除與成員刪除都因外鍵限制直接失敗、
   改歸屬把資料留在原成員卻回報「搬移 0 筆」看似成功、只有 CPAP 的成員檢視頁
   整片空白。**規則：補值不能防再犯，要用 DDL 對帳把清單釘住**
   （`tests/engine/table_coverage.test.mjs`）。
3. **注入式測試對宿主權限層完全盲。** 210 個測試全綠，實機第一步就炸在
   Tauri fs scope 不匹配 leading dot。驗這類問題要用「模擬 scope 的 fs stub」
   跑真實素材，並拿修復前版本做負向對照確認 stub 真的抓得到。

### 上架（直接分發）

目標已定為**直接分發**（GitHub release／自己網站），不走 Mac App Store。
現況會被 Gatekeeper 擋，因為產物未簽章也未公證。

- **硬前提**：Apple Developer Program 付費會員（US$99／年）。免費帳號可以
  簽章但**不能公證**，而 Gatekeeper 擋的正是未公證。帳號尚未購買（2026-08-14
  當日決定隔日研究）。
- CI 已在用 `tauri-apps/tauri-action`，**補環境變數即會自動簽章、公證、
  stapling**，不需改建置架構。需要六個 GitHub Secrets：`APPLE_CERTIFICATE`
  （.p12 的 base64）、`APPLE_CERTIFICATE_PASSWORD`、`APPLE_SIGNING_IDENTITY`
  （`Developer ID Application: …`，**不是** Apple Distribution，那是 App Store 用的）、
  `APPLE_ID`、`APPLE_PASSWORD`（app-specific password）、`APPLE_TEAM_ID`。
- 待做：`release.yml` 接線（沒有 Secrets 時要跳過而非失敗）＋ 產出後以
  `spctl -a -vvv -t install` 與 `xcrun stapler validate` 對 DMG 斷言，讓
  「有沒有真的公證成功」由 CI 擋下而不是等使用者回報。
- Windows 的 SmartScreen 是另一回事（需 code signing 憑證，EV 一年 300 美金
  起，且新憑證要累積信譽），先解 macOS 較划算。

### 出貨前該關的門（不需付費帳號，可先做）
