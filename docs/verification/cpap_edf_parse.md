# 驗收紀錄：EDF 解析純函式（change cpap-sleep-therapy 第 2 組）

僅記結構性結論，**不含任何個人健康數值**（依 design D12）。

## 驗證策略

本輪明示豁免「每個 adapter 都有 Python oracle 差分對帳」紀律（假設 #65），
替代方案必須自身夠強，否則就是把護欄拆了沒補回去。實際做了三層：

1. **合成 fixture 的數值斷言**（`tests/adapters/edf_parse.test.mjs`，16 項）：
   人為指定數位值、人工算出物理值，逐項比對。不做往返比對。
2. **產生器與解析器獨立**（`tests/helpers/make_edf.mjs`）：產生器刻意不
   import `edf.js` 的任何常數或函式，位移與欄位寬度各自照 EDF 規格寫死。
   共用同一份佈局假設的話，兩邊一起錯也會通過。
3. **對真實檔案交叉比對另一個獨立實作**：真實素材不是本專案產生的，
   這是最強的一層。結果見下。

## 本組修正的一個 design 錯誤（重要）

design 原本三處寫明缺測判定 MUST 用 **`dig == digMin`**。這是錯的，
而且是**雙向都錯**的那種錯：

- 縮放公式 `phys = physMin + (dig − digMin) × …` 在 `dig == digMin` 時
  恆等於 `physMin`，不可能得出實測觀察到的 −1／−0.02／−0.1。回推可知
  缺測的原始數位值是 **−1**，而 `digMin` 多半是 0 或正數。
- 因此 `== digMin` 會**漏掉全部缺測日**（於是趨勢圖畫出整片假點，正是
  design 宣稱要防的事），同時**誤刪合法的 0 值**（實測有數百天的分項
  指數真的是 0、壓力欄真的等於 `digMin`，會全部被抹成 NULL）。

正確判準是 **`dig < digMin`**（EDF 規格要求數位值落在 `[digMin, digMax]`，
超出範圍者不是量測值）。已修正 `edf.js`、design、proposal、tasks、handoff
與 common-ground 假設 #70。

**此錯誤是寫測試時被發現的**：斷言「同一個哨兵值在不同訊號縮放成不同
物理值」跑出兩邊都是 0，才回頭發現前提錯了。純文件審查不會抓到它，
因為那三處寫得很篤定，而且彼此一致。

## 其他由測試或 diff 全讀抓到並修掉的問題

- `recordCount` 為 −1（EDF 規格允許，表示錄製中筆數未知）時，與資料長度
  直接取 `min` 會得 −1，整個檔案被靜默當成零筆。改為以資料區長度為準。
- 合成產生器原本以 `digMin` 補滿不足的樣本，但 `digMin` 是合法值
  （`Pulse` 的 18 bpm）。改用與真實來源一致的 −1。
- 原本宣告了 `MAX_EDF_BYTES` 常數並註明它防記憶體成長，但沒有任何地方
  檢查它。宣告了卻不實施的防護比沒有更糟（會讓人以為有把關）。已移除，
  並把上限改列在真正能實施的那一層（tasks 3.1 的讀檔前檢查）。
