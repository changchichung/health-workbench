# app-import-gui — 匯入紀錄卡的批次摺疊與批次救援

## ADDED Requirements

### Requirement: 匯入紀錄卡的批次摺疊與批次救援

App 的匯入紀錄卡 MUST 將同一批來源檔案（同 adapter ＋同匯入時刻）摺疊為
一列，顯示檔案數與該批各表合計，並可展開檢視逐檔。一次多檔匯入會產生
數十筆來源紀錄，逐列呈現使該區塊無法閱讀。

批次列 MUST 提供對**整批**生效的刪除與改歸屬；逐檔操作 MUST 保留在展開
後的每一檔上：刪除單一逐日檔仍有正當用途（某檔解析錯誤要單獨移除重匯），
而只能逐檔操作等於沒有解決可讀性問題。

批次操作 MUST 在單一交易內完成，全成功或全回復。執行前 MUST 顯示整批的
影響範圍（檔案數與各表筆數合計）並要求確認。

缺少匯入統計的批次 MUST 明示為「無統計」，MUST NOT 顯示為新增 0 筆：
兩者在畫面上是不同的事實。

批次的組成 MUST 由檢視層計算後傳入引擎層，引擎層 MUST NOT 自行推導批次：
分組規則屬於呈現層的決定，引擎不該知道。

#### Scenario: 多檔匯入後的紀錄呈現
- **WHEN** 拖入一整張 CPAP 記錄卡後檢視匯入紀錄卡
- **THEN** 該批顯示為一列「N 個檔案」與該批各表合計，展開後可見逐檔檔名
  與各檔自己的操作入口

#### Scenario: 剔除整批
- **WHEN** 於批次列選擇剔除整批並確認
- **THEN** 確認面板先列出檔案數與各表筆數；確認後該批全部來源紀錄與其
  資料列於單一交易內清除，其他批次與其他成員的資料不變

#### Scenario: 批次操作中途失敗
- **WHEN** 批次刪除或改歸屬在中途失敗
- **THEN** 全庫回復至操作前狀態（無半刪半搬），並顯示失敗訊息

#### Scenario: 單檔批次
- **WHEN** 某批只有一個檔案（健保與 Apple 皆為單檔匯入）
- **THEN** 該列直接顯示檔名與單檔操作，不出現「1 個檔案」的摺疊層
