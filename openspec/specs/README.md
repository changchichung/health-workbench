# specs 目錄說明

本目錄是規格的單一事實來源（Spectra SDD）。每份 spec 描述「系統應該如何」，
可獨立閱讀，不需要參照開發過程紀錄。

## 關於 `@trace` 區塊中的 `docs/` 路徑

各 spec 末尾的 `<!-- @trace -->` 會列出該需求對應的產物，其中指向
`docs/verification/`、`docs/*handoff*.md` 的路徑**不在本倉庫內**。

那些是開發過程紀錄（驗證紀錄、交接文件、proposal 與 design），刻意不進公開
倉庫：它們的存在目的就是記錄對真實資料的實測，而實測來源是真人的健康資料。
即使只寫筆數、天數與序列點數，合起來仍構成可辨識的健康輪廓，因此保留在
開發者本機。

trace 條目仍然保留，因為它記錄的是「這條需求驗證過，證據叫什麼名字」，
這個資訊本身有意義；只是外部讀者無法開啟該檔案。

## 這裡的內容不得出現實測數字

specs 描述行為與約束，不描述某一份真實資料長什麼樣。效能類要求請寫量級
（「百 MB 量級檔案 MUST 於 60 秒內完成匯入」），不要寫某個實際檔案的大小
與筆數。`app/tests/knowledge/public_repo_pii.test.mjs` 會擋下違反者。
